# GenForm Plugin Development Boilerplate & Setup Guide

This document outlines the mandatory conventions, standards, and setup required for developing the GenForm WordPress plugin (v1.0.0 Free Core).

## 1. Plugin Constants & Root Setup

All main constants must be defined within the main plugin file (`genform.php`) to ensure easy access to file paths and URLs.

```php
// Define Constants
if ( ! defined( 'GENFORM_VERSION' ) ) {
    define( 'GENFORM_VERSION', '1.0.0' );
}
if ( ! defined( 'GENFORM_PLUGIN_FILE' ) ) {
    define( 'GENFORM_PLUGIN_FILE', __FILE__ );
}
if ( ! defined( 'GENFORM_PLUGIN_PATH' ) ) {
    define( 'GENFORM_PLUGIN_PATH', plugin_dir_path( __FILE__ ) );
}
if ( ! defined( 'GENFORM_PLUGIN_URL' ) ) {
    define( 'GENFORM_PLUGIN_URL', plugin_dir_url( __FILE__ ) );
}
if ( ! defined( 'GENFORM_PLUGIN_DIRNAME' ) ) {
    define( 'GENFORM_PLUGIN_DIRNAME', dirname( plugin_basename( __FILE__ ) ) );
}
```

## 2. Text Domain and Localization

*   **Text Domain:** Must be `genform`.
*   **Loading:** The text domain must be loaded using `load_plugin_textdomain()` on the `plugins_loaded` hook.
*   **Path:** The language files must reside in the `/i18n/` directory.

```php
// Example: Load Text Domain
function genform_load_textdomain() {
    load_plugin_textdomain( 'genform', false, GENFORM_PLUGIN_DIRNAME . '/i18n/' );
}
add_action( 'plugins_loaded', 'genform_load_textdomain' );
```

## 3. Class Naming Convention & Structure

All classes must follow an object-oriented naming convention to prevent conflicts and ensure clarity.

*   **Prefixing:** All core classes must be prefixed with `GenForm_`.
*   **File Naming:** File names should be lowercase, with hyphens replacing underscores (e.g., `class-genform-admin.php`).

| File Location | Class Example | File Name Example |
| :--- | :--- | :--- |
| `/includes/` | `GenForm_Form_Core` | `class-genform-form-core.php` |
| `/admin/` | `GenForm_Admin_Settings` | `class-genform-admin-settings.php` |
| `/public/` | `GenForm_Shortcode` | `class-genform-shortcode.php` |

## 4. Hook Naming Convention

All custom hooks (actions and filters) must be properly prefixed to avoid conflicts with other plugins.

| Hook Type | Example Hook Name |
| :--- | :--- |
| Action | `do_action( 'genform/after_submission', $entry_id, $form_id );` |
| Filter | `apply_filters( 'genform/form_data_sanitization', $data );` |

## 5. Activation and Deactivation Hooks

The plugin must handle activation and deactivation cleanly, specifically for database and rewrite rule setup.

*   **Activation Hook:** Used for creating necessary database tables (`wp_genform_entries`, `wp_genform_forms`) and setting initial options.
*   **Deactivation Hook:** Used for cleanup (optional, but good practice). Do not delete user data on deactivation.

```php
// Example: Register Hooks in genform.php
register_activation_hook( GENFORM_PLUGIN_FILE, 'genform_install' );
// register_deactivation_hook( GENFORM_PLUGIN_FILE, 'genform_uninstall' ); // Optional cleanup
```

## 6. CSS and JavaScript Enqueuing

Scripts and styles must only be loaded where they are absolutely needed (conditional loading).

*   **Admin:** Load Admin assets only on `genform` related admin pages (`admin_enqueue_scripts`).
*   **Frontend:** Load form-specific assets only when a GenForm shortcode or block is detected on the page (`wp_enqueue_scripts`).
*   **Prefixing:** Use `genform-` prefix for all handle names (e.g., `wp_enqueue_script( 'genform-builder-js', ... );`).
