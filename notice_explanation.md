# WordPress Plugin Review Notice Explanation

This document explains the issues highlighted in the plugin review and the steps taken to resolve them.

## 1. Use `wp_enqueue` Commands

**Issue:**
The plugin was including JavaScript variables directly in the PHP file using `<script>` tags.

```php
<script type="text/javascript">
    var genformInitialData = ...;
</script>
```

**Why it's a problem:**

- **Security:** Inline scripts can be blocked by Content Security Policies (CSP).
- **Performance:** It breaks caching and dependency management. WordPress cannot control when or where this script loads.
- **Maintainability:** Mixing PHP and JS logic makes the code harder to debug.

**The Fix:**
We moved the data passing to the standard WordPress function `wp_localize_script`.

- **File:** `includes/class-genform-core.php`
- **Method:** `enqueue_admin_assets`
- **Action:** We now fetch the form data in the PHP class and pass it to the registered script `genform-builder-js` using `wp_localize_script`.
- **JS Update:** Updated `assets/js/form-builder.js` to read from the localized object `genformBuilder.initialData` instead of a global variable.

## 2. Nonces and User Permissions

**Issue:**
The reviewer noted missing nonce checks for input calls (`$_GET`, `$_POST`).

```php
$genform_form_id = absint( $_GET['form_id'] );
```

**Why it's a problem:**

- **CSRF (Cross-Site Request Forgery):** Without a nonce, an attacker could trick an admin into clicking a link that performs an action (like deleting or editing a form) without their intent.
- **Authorization vs. Intent:** `current_user_can` checks *if* the user is allowed to do something. A Nonce checks *if* the user actually intended to do it right now. Both are needed.

**The Fix:**
We added nonce verification to all actions involving `$_GET` parameters that trigger a view change or action.

1. **Forms List (`admin/views/forms-list.php`):**
    - Added `wp_nonce_url` to the "Edit" and "Entries" links. This appends a unique security token to the URL.

2. **Form Builder (`admin/views/form-builder.php`):**
    - Added a check at the top of the file:

      ```php
      if ( ! isset( $_GET['_wpnonce'] ) || ! wp_verify_nonce( ..., 'genform_edit_form' ) ) {
          wp_die( ... );
      }
      ```

    - This ensures that the "Edit" page can only be accessed via a valid link generated by WordPress.

3. **Entries List (`admin/views/entries-list.php`):**
    - Added a similar nonce check when filtering entries by `form_id`.

## Summary of Changes

- **`admin/views/forms-list.php`**: Added nonces to action links.
- **`admin/views/form-builder.php`**: Removed inline script, added nonce verification.
- **`admin/views/entries-list.php`**: Added nonce verification.
- **`includes/class-genform-core.php`**: Implemented `wp_localize_script` to pass data securely.
- **`assets/js/form-builder.js`**: Updated to use the new localized data object.

These changes ensure your plugin adheres to WordPress security standards and best practices.
